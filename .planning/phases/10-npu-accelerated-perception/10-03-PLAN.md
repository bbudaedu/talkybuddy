<objective>
執行 D-02 停損檢查點的**唯一有效測試**：繞過 sherpa-onnx 的便利包裝，直接用 raw
`onnxruntime.InferenceSession` 掛 `NeuronExecutionProvider` 載入 SenseVoice 模型，並用 10-02 的
證據層量出「到底有幾個算子真的被排到 NPU 上」。

Purpose: RESEARCH.md Summary 與 Pitfall N1 已證實 sherpa-onnx 的 Python API 把 `provider` 參數
硬限制在 `cpu | cuda | coreml`，provider 白名單寫死在其 C++ 核心的編譯期，Python 層沒有任何
逃生門可以把 `NeuronExecutionProvider` 交給底層 session。因此「在既有 ASR 引擎改一個參數」
這條路在本 codebase 上**不成立**；raw session 是本 phase 唯一能在 Day 1 產生可證偽答案的路徑。

本計畫刻意**不**做 fbank 前處理、**不**做解碼、**不**求正確逐字稿——只餵零值假輸入，
目的僅是讓 ORT 完成 graph partition 並吐出節點放置日誌。這是「最小可證偽測試」的定義：
用最少的工程量取得 go/no-go 訊號。真正的前處理與解碼要等 10-04 判定 GO 之後才在 10-05 動工。

Output: 一支可在真機獨立執行的 spike 腳本、其純函式測試，以及一份存放真機原始輸出的證據檔。
本計畫**不**修改 `server/` 任何既有檔案，對 Phase 8 CPU 基線零風險。
</objective>
