<objective>
把「中途斷網會多秒靜默 hang」這個 NETCUT-02 的核心症狀，用 D-03 鎖定的手段（縮短逾時、不做取消機制）解掉——但只縮短**雲端專屬**的內層逾時，並明確保住 edge 引擎的生存空間；同時補上唯一一個真正繞過 kill-switch 的背景出境側通道。

Purpose: D-03 點名三個常數要「大幅縮短」，但 RESEARCH.md Pitfall 2 以 Phase 8 真機數據證明其中的 `server/pipeline.py::LLM_TIMEOUT_S` 是 cloud 與 edge **共用**的外層包裝（`for engine in engines:` 迴圈對每個引擎套同一個值），而真機上 edge LLM 單階段實測可達 4170ms（`edge/EDGE_TURN_LOOP_VALIDATION.md:57`）。把它砍到 1-2 秒會讓每一次離線回覆都被截斷、退化成 scaffold——正好摧毀 Phase 8 剛以存亡代價換來的成果。因此本 plan 執行 D-03 的**意圖**（雲端 LLM/TTS 快速降級）而非其字面清單：只縮短兩個雲端專屬內層逾時，`LLM_TIMEOUT_S` 維持 8.0 並用常數契約測試把「不准有人日後把它一起砍掉」寫成結構性守門。此調和已在本 phase 交付回報中向使用者明列。

同時處理 RESEARCH.md Pitfall 4：`VoicePipeline._refresh_directive()`（每 5 個成功回合背景觸發）呼叫的 `diagnose.generate_diagnosis()`，其雲端分支只受憑證與家長同意兩道閘門，**完全不看 network_mode**。今天的示範機沒有雲端憑證所以低風險，但本 phase 給 kill-switch 的新敘事是「開關＝這台裝置現在零出境呼叫」，這個側通道會讓該敘事在 Phase 11 把憑證放上同一台機器之後直接破功。修法是一個 kwarg 加一個條件式。

Output: 兩個縮短後的雲端逾時常數（皆可 env 覆寫）；`LLM_TIMEOUT_S` 的解耦註解；`generate_diagnosis(allow_cloud=...)` 閘門；兩個新測試檔（逾時隔離契約 + 背景側通道閘門 + `/api/status` 零出境證據）。
</objective>
