## Phase Scope Note

本 phase（Network-Cut Demo Hardening）**不新增任何 UI 元件**。09-CONTEXT.md 已鎖定 D-01～D-05：kill-switch 沿用/改造既有 `web/index.html` 的 `airplaneSwitch`/`modeBadge`/`applyMode()`（lines 194, 201-206, 303-306, 684-732），不做主持人專用畫面、不加確認機制、不做實體斷網。因此本 UI-SPEC 的範圍僅限：

1. **既有 online/offline 徽章（`modeBadge`）是否需要視覺強化**以滿足 ROADMAP Phase 9 success criteria #3「明確可見的 online/offline 狀態切換，讓觀眾能親眼確認離線宣稱」→ 見「Badge Visual Strengthening」一節。
2. **切換瞬間的 toast 文案是否需要微調**以呼應斷網示範敘事（09-CONTEXT.md Claude's Discretion 明列此為 executor 可自行決定、非新決策）→ 見「Copywriting Contract」一節。
3. **明確劃出非本 phase 範圍**，避免 planner 誤讀「明確可見」需求而發明新元件 → 見「Explicit Non-Scope」一節。

其餘四個既有互動元素（`modeBadge`、`airplaneState`、`airplaneSwitch`、toast）的結構、位置、觸發邏輯、後端契約皆維持不變，僅做本文件列出的 CSS/文案級微調。

## Badge Visual Strengthening（NETCUT-02 / ROADMAP #3）

**評估結論：現況 `modeBadge`（色票區分 edge 綠／cloud 藍 + dot + 文字，`web/index.html:194,692-703`）在功能上已滿足「明確可見的 online/offline 狀態切換」——切換時色彩、文字、`airplaneState` 副標三處同步變化，語意已足夠清楚。但 badge 目前置於密集的 `.statusbar`（與延遲、待同步筆數、連線狀態並列，12px 小字），對舞台距離的觀眾/評審而言辨識度偏低。**

09-CONTEXT.md `<deferred>` 已明確排除「戲劇化改版（大徽章/全螢幕狀態轉場）」，因此本節僅給出**同一元件內的低風險強化**，不新增元件、不改變版面位置：

| 項目 | 現況 | 建議值 | 理由 |
|------|------|--------|------|
| `.badge` padding | `3px 10px` | `4px 12px` | 落回 4px 網格，視覺量體 +20~30%，不換行不擠版 |
| `.badge .dot` 尺寸 | `8px × 8px` | `12px × 12px` | 色彩指示點更容易從遠處辨識，仍在 4px 網格內 |
| 狀態切換時的一次性動效 | 無 | `.badge.pulse{animation:badgePulse .6s ease-out;}`（scale 1→1.18→1，沿用既有 `@keyframes` 慣例如 `talkBeat`/`pulseThink`） | 只在「使用者主動切換」瞬間吸引目光，5 秒輪詢的被動刷新不觸發，避免視覺干擾 |
| 字重 | `700` | **不變更** | 維持既有 2 種字重清單（700/800），不新增第 3 種，降低風格風險 |
| aria-live | 無 | 建議（非阻擋）：`modeBadge` 或其容器加 `aria-live="polite"` | 額外的可及性加分，非本 phase 必要條件 |

**觸發規則（給 executor）：** `pulse` class 只能在 `airplaneSwitch` 的 click handler 內、`/api/network_mode` fetch 成功回呼時（即 `web/index.html:715` `applyMode(target)` 呼叫後）加上，並於動畫結束後移除；**不得**在 `refreshStatus()` 的 5 秒輪詢路徑（`web/index.html:685-690`）觸發，否則 badge 會每 5 秒閃一次，造成觀眾誤判與視覺疲勞。

此強化為**建議而非阻擋項**——若 executor 時間預算不足，維持現況 badge 亦已符合 NETCUT-02 字面要求；但若採用，必須完全遵守上表數值與觸發規則，不得自行放大尺寸或改變版面位置。

## Explicit Non-Scope

本 phase 的 UI 表面鎖定為「4 個既有元素（`modeBadge`、`airplaneState`、`airplaneSwitch`、toast）」的 CSS/文案級微調。以下項目明確排除；若後續 plan 出現以下任一項，視為超出本 UI-SPEC 契約，需回頭與使用者確認，而非逕行實作：

- 不新增任何 UI 元件、頁面或路由（no new component/page/route）
- 不做主持人專用畫面／獨立操作介面（no host-only view）——D-04 鎖定沿用學生畫面既有按鈕，不另開路由，不做鍵盤快捷鍵
- 不加確認對話框、長按、雙擊等防誤觸機制（no confirmation dialog）——D-05 鎖定單點即切、維持現狀行為
- 不做「戲劇化」badge 改版（大徽章、全螢幕狀態轉場、進場動畫序列等）——09-CONTEXT.md `<deferred>` 已明確列為本輪不選；本 UI-SPEC 僅允許「Badge Visual Strengthening」一節列出的既有元件內微調（padding/dot 尺寸/一次性 pulse 動畫）
- 不新增顏色 token 或第三種 badge 狀態色（僅維持既有 edge 綠／cloud 藍二態）
- 不因斷網示範新增 loading spinner／骨架屏——既有 `.switch:disabled{opacity:.5}`（`web/index.html:77`）已是 fetch 期間的既有視覺回饋，維持現狀即可
- 不變更 `/api/status` 5 秒輪詢的呈現邏輯，也不新增「輪詢已暫停」的 UI 提示——NETCUT-02 的輪詢暫停屬後端行為判斷（見 09-CONTEXT.md Claude's Discretion：executor 依實際程式碼掃描後決定範圍），非本 UI 契約範圍
- 不引入真實實體斷網（拔線/關 AP）相關的任何 UI 狀態（如「Wi-Fi 圖示」）——D-01 鎖定純軟體 toggle，不做實體斷網視覺
