# Prompt 排序最佳化：實測後放棄（2026-07-27，Genio 520 真機）

## 動機

Phase 8 真機實測單回合分解：`{'asr': 405, 'llm': 4170, 'tts_first': 1209, 'round_total': 5852}`（ms）。
LLM 佔 71%，其中 prompt 重算約 2.05s。Phase 8 的 carried-forward item 提議把固定的回覆規則
從 user message 尾巴移進 system prompt，估計省 1–1.5 秒。

原本的 user message 排序確實是 KV cache 的最壞情況：

```
學生剛剛說：「{student_text}」   ← 每回合必變，排最前
目標英文句：{target}
{directive_block}
請照規則回覆：先一句繁體中文稱讚鼓勵，再用「跟我說一遍：<英文句>」帶讀目標英文句。   ← 完全固定，排最後
```

兩個連續回合的共同前綴只有 **8 個字**。

## 快取面：改動有效，且效果比預估更好

把固定規則移進 system 段、user 段改為「越穩定越前面」（target → directive → student_text）後，
於真機 llama-server（qwen2.5-1.5B Q4_K_M、threads=6）實測 `timings.prompt_n` / `prompt_ms`：

| 排序 | 穩態 prompt_n | 穩態 prompt_ms |
|---|---|---|
| 原本 | 57–58 | 1669–1679 ms |
| 改後 | **13–14** | **441–476 ms** |

**省約 1.2 秒／回合**，落在 Phase 8 估計的 1–1.5s 區間內。

## 行為面：改動破壞了核心產品行為，因此放棄

同一顆 llama-server、同樣 5 組測試輸入、temperature 0.7，逐條檢查三條規則：

| 版本 | 規則一：中文稱讚 | 規則二：帶讀格式 | 規則二：目標句逐字 | 中位 prompt_n |
|---|---|---|---|---|
| **原本排序** | **5/5** | **5/5** | **5/5** | 57 |
| 規則進 system + 版面說明 | **0/5** | 5/5 | 5/5 | 23 |
| 上者 + 尾端短錨點「請開始回覆。」 | **0/5** | 2/5 | 5/5 | 29 |
| 尾端短指令「請先稱讚再帶讀。」 | 3/5 | 3/5 | 1/5 | 32 |
| 尾端中指令「請先用中文稱讚，再帶讀目標句。」 | 5/5 | 5/5 | 4/5 | 37 |
| 目標句移到最前 + 保留原尾巴 | 5/5 | 5/5 | **2/5** | 59 |

改後的回覆長這樣（稱讚整句消失）：

```text
跟我說一遍：I like apples.
```

原本的回覆：

```text
很好，你已經會說了！跟我說一遍：I like apples.
```

## 結論

**放棄此最佳化，還原原本排序。** 三個理由：

1. **指令的鄰近性正是合規的來源。** 把固定規則搬離生成點，省下的是重算成本，
   賠掉的是模型照規則做事的機率。這不是最佳化，是一筆隱含的交易。
2. **稱讚鼓勵不是裝飾。** 這是兒童英語鷹架學伴的核心體驗，`_SYSTEM_PROMPT` 規則一
   把它列為第一條不是偶然。用它換 1.2 秒，對這個產品是壞交易。
3. **沒有中間解。** 六種變體全試過：唯一同時保住稱讚與帶讀的（尾端中指令）
   仍在目標句逐字上掉到 4/5，而目標句逐字是 Phase 5 coach-style follow-along
   的教學基礎。且 n=5、temperature 0.7 的樣本太小，不足以支撐更細的取捨。

## 給後續的人

- **不要只用延遲指標驗收 prompt 改動。** 本次若只看 `prompt_ms`，會得到「省 1.2 秒、
  成功」的錯誤結論並上線。必須同時逐條檢查產品規則的合規率。
- 若未來仍要壓這 1.2 秒，可行方向是**換模型或加 speculative decoding**，
  而不是搬動指令位置。
- 量測腳本形式保留於本檔的表格；真機 llama-server 啟動方式：
  `./edge/deploy/bin/llama-server -m models/qwen2.5-1.5b-instruct-q4_k_m.gguf --host 127.0.0.1 --port 8080 --threads 6 -c 512`
